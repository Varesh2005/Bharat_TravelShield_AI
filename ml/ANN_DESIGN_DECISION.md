# ANN Design Decision (Bharat-TravelShield AI, ML module)

Scope: this is an **ANN course mini-project**. The ANN/MLP is the primary model
for every supported hazard. Logistic Regression, Random Forest, persistence and
climatology exist only to answer: *does the ANN add value?* Numbers quoted here
come from `ml/EVALUATION_REPORT.md` / `research/experiments/<hazard>/results.json`
(generated by `python -m ml.hazard_training --hazard all`); re-run to refresh.

Sources read: `ANN work distribution.pdf` (Varesh section) and
`TRAVELRISK_AI_Implementation_Plan.pdf` (sections 4, 6, 7).

## 1. What the data can support (evidence, not preference)

All processed sources are **annual**. There is no daily/monthly table in the
repository, so the plan's "destination + travel date" input cannot be answered
at travel-month resolution. Every model therefore predicts **next calendar year,
per district**. Seasonal/monthly features (cyclic month, monsoon flag, rolling
weather) are not possible and are not used.

| Hazard | Label source | Geography | Label years | Status |
|---|---|---|---|---|
| Heatwave | NASA POWER Tmax >= 45 degC (derived) | district, 640 | 2011-2025, complete | **supported** |
| Flood | India Flood Inventory v3, presence-only | district, 502 mapped | 1967-2023 | **supported with caveats** |
| Malaria | NCVBDC reported counts (FULL_YEAR rows) | district, 517 | 2011-2023 modelled | **supported** |
| Dengue | NCVBDC state counts | **state**, 36 | 2021-2025 full years | **unsupported** |
| Chikungunya | none | - | - | **unsupported** |

Readiness is computed, not asserted (`python -m ml.hazard_datasets --readiness`).
Criteria used: at least 300/100/100 rows in train/val/test and at least 20
examples of each class in every split, under the chronological split below.

* **Dengue** fails: labelled state-year transitions per split are train 0, val 0,
  test 143. Only five full years exist, so no training period before 2020 exists, and
  the labels are state-level (district labels would be copies, not independent
  truth). The West Bengal 2024 record (`West Bengal*`, 441) is `verification_pending`
  and would need excluding anyway. Recovery path: a longer state-year (ideally monthly)
  series; then rerun the readiness check.
* **Chikungunya**: no data exists anywhere in the repository.

## 2. Targets, horizon, geography

All targets are binary for year T+1 using only information known at the end of year T.

* **heatwave** `target_heat_next_year`: >= 1 day with modelled Tmax >= 45 degC. A
  temperature-threshold indicator from gridded data, **not** an IMD-declared heatwave.
* **flood** `target_flood_next_year`: the inventory records >= 1 flood event for the district.
  Negatives mean "none recorded". Districts with no recorded event at all cannot be told apart
  from unmapped districts and are excluded (138 of 640), which may overstate flood-proneness. The cohort rule
  uses no future information: a district is in scope only if its first recorded event is on or before the training
  cutoff (2019); all 502 qualify, so no district enters because of validation/test labels (unit-tested).
  The explicit decision to encode "no row" as 0 *for this presence-only target and its history
  features* is limited to this hazard and is stated in every output.
* **malaria** `target_malaria_high_next_year`: reported cases per 100,000 (2011 population) in the
  top quartile of all reporting districts in year T+1. A relative target is used because national
  totals fell from 1.07M (2011) to 0.12M (2021); a fixed threshold would measure the decline, not
  risk. 2024 is a partial year and is never used. It is a ranking of reported burden, not an
  absolute risk and not corrected for under-reporting.

## 3. Features and missing-data policy

Three groups per hazard (`ml/data/hazards/<hazard>/feature_dictionary.csv`):
geography (latitude, longitude, log population), weather in year T (annual NASA POWER summaries)
and hazard history (heatwave days T and T-1; recorded flood events T/T-1 and flood years in the last
5/10; malaria log-incidence T/T-1, national rank percentile and a top-quartile flag in T).

Rows with any missing required input are **dropped and counted**; nothing is imputed. A malaria
district-year without a FULL_YEAR record is unknown and simply absent. Dengue is not used as a feature
(state-level and 2021+ only).

## 4. Leakage-safe evaluation

* **Chronological split by target year** (same for all hazards and all models): train <= 2019,
  validation 2020-2021, test >= 2022. No random row split. A unit test perturbs every year after
  T and checks that all features of year T are unchanged.
* The scaler is fitted on train only. Hyper-parameters, early stopping, Platt calibration and the
  decision threshold use **validation only**. The ANN is trained on train years only (not refitted
  on train+validation) so the validation-fitted calibration stays valid. Test years are scored once.
  A unit test shuffles the test labels and checks that the network weights, threshold and
  calibration are bit-identical.
* **Held-out geography**: ~20% of states are removed from train/validation and the models are
  tested on later years in those unseen states (spatiotemporal test).
* The malaria label threshold uses only the target year's own cross-section; it is a label
  definition, never a feature.
* The test years are described honestly in section 8: they are exploratory-informed, not a pristine final test.
* Disclosed limits: validation is used for several jobs; the validation window is only two years
  (for heatwave it contains the anomalous 2021, 4.7% positive nationally vs 37.5% in test, which
  directly causes the heatwave calibration failure in section 8).

## 5. Primary ANN architecture

A dense multilayer perceptron, chosen because inputs are structured, low-dimensional annual
district features with no ordered sub-annual sequence (so no GRU/LSTM, no Transformer, no graph model).

```
input (12-14 standardised features)
  -> Dense(h1) ReLU -> Dense(h2) ReLU -> Dense(1) sigmoid
loss: binary cross-entropy   optimizer: Adam (lr 0.001)   batch size 128
L2 weight decay alpha in {0.001, 0.01}   max 200 epochs
early stopping: stop after 15 epochs without validation-loss improvement, keep the best epoch
class imbalance: optional random oversampling of the minority class in the training set only
seed 42
```

Grid (12 configs, fixed in code): hidden (32,16)/(64,32)/(128,64) x alpha x oversampling on/off,
selected by **validation PR-AUC**. Selected: heatwave (32,16) alpha 0.001; flood (128,64) alpha
0.001; malaria (64,32) alpha 0.01 (see model cards for epochs). Implemented with scikit-learn
`MLPClassifier.partial_fit`, trained epoch by epoch so early stopping uses the chronological
validation years rather than a random internal split. Seed stability is reported over 5 seeds.

## 6. Separate hazard ANNs, not a multi-task ANN

The plan lists a shared-trunk multi-task network as a candidate. It is **not adopted**, on evidence:
the hazards differ in label geography and coverage (heatwave 640 districts; flood 502; malaria 517;
dengue state-level), target definitions (threshold occurrence vs presence-only vs relative rank), and
missingness. A joint model would have to train only on the districts that carry every label (or
use label masking), shrinking the data and mixing label reliabilities. Three small independent ANNs
with identical architecture families are easier to validate, explain in a viva and extend. A masked
multi-task experiment remains a possible future ablation, not an assumption.

## 7. Baselines and acceptance criteria

Baselines run on the identical rows: persistence (last year repeats), district climatology
(training-period event rate), Logistic Regression and Random Forest (hyper-parameters chosen on
validation PR-AUC). LightGBM is not installed in the environment and is omitted (documented, not
faked). All models receive the same validation-based Platt calibration and F1 threshold rule.

Pre-stated reading rules: the ANN "adds value" for a hazard only if its held-out PR-AUC exceeds
persistence **and** matches or exceeds the best non-neural baseline within seed noise. Reporting is
per model, never accuracy alone: precision, recall, F1, macro-F1, PR-AUC, ROC-AUC, Brier, log-loss,
ECE with a reliability table, confusion matrix, prevalence, per-year and per-state results, false
positive/negative analysis and a feature-group ablation.

**Outcome against that rule** (numbers in `ml/EVALUATION_REPORT.md`): the ANN beats persistence and climatology on PR-AUC
for all three hazards, but it does **not** exceed the best non-neural baseline on any of them. Flood: it matches
logistic regression and random forest within seed noise. Heatwave and malaria: logistic regression is better by more than
the 5-seed standard deviation. The honest claim is "a working, validated, competitive ANN", not "the ANN is best".

## 8. Calibration, risk bands, uncertainty

* Raw network output is called a **raw model score**. It is Platt-calibrated on validation data.
* **Probability-display rule (decided on validation years only).** Platt scaling is fitted on the earlier
  validation target year(s) (2020) and its ECE is measured forward on the last validation year (2021). The
  probability, decision threshold and class are shown only if that ECE is <= 0.10; test years take no part
  in the decision (a unit test shuffles the test labels and checks that the decision is unchanged). The 0.10
  limit is a conventional engineering value adopted after the first exploratory run, not tuned per model.
  Outcome: malaria (ECE 0.056) is shown; **heatwave (0.173) and flood (0.149) are withheld** and only the raw
  ranking score is returned. Flood is withheld because its event base rate differs between the two
  validation years (47% in 2020, 33% in 2021), so an absolute probability is not stable across years.
* **Status of the test evidence.** An earlier version of this rule used test-year ECE, and the test years were
  first scored in that exploratory run. After the change nothing that decides a model, threshold, calibration or
  display uses them, and the models, thresholds and metrics are bit-identical (verified by comparing weights and
  results before and after). The test results are therefore held-out but exploratory-informed, **not a pristine
  final test**, and no unseen period remains in the data. Test ECE is reported for information only.
* **Low/Medium/High bands are unavailable for every hazard.** No band thresholds have been selected and
  validated; inventing them would be arbitrary. The interface returns `risk_band: null` with a reason.
* Risk, data coverage and model reliability are separate fields. Missing inputs give
  `status: unavailable`, never a normal-looking score.
* Why heatwave fails: validation prevalence is 19.4% (it contains 2021, only 4.7% positive) while test
  prevalence is 37.5%. Platt scaling learns the validation base rate, so on test it makes calibration worse
  (ECE 0.121 raw -> 0.221 calibrated; information only) and the validation-chosen threshold (0.35) is too strict
  (test recall 0.35). The validation-only forward check catches the same problem (0.173) without test data.
  Validation ECE after fitting (0.03-0.04) is in-sample and is not evidence of calibration.
* When the probability is withheld the class is withheld too (no predicted_class/predicted_label), because the
  threshold lives on the calibrated-probability scale.
## 9. Explainability

Global: permutation importance on the validation set (drop in PR-AUC). Local: occlusion, i.e. the
change in the output when one input is replaced by its training median. Both are model-agnostic,
cheap to demonstrate and explicitly labelled approximate and non-causal. SHAP was not added (it is a
tree-model default and not clearly explainable for this MLP in a viva).

## 10. Claims that can and cannot be made

Can: for each supported hazard, a reproducible ANN with documented target, split, baselines and
held-out (exploratory-informed, not pristine) metrics; honest statements of where the ANN equals or trails simpler models.
Cannot: month- or travel-date predictions; official IMD heatwave or confirmed-flood predictions;
absolute malaria risk; any dengue or chikungunya prediction; a trustworthy heatwave probability;
Low/Medium/High bands; that the ANN beats the baselines (it does not on every hazard, see the report);
causal explanations.

## 11. Second review: checks run and defects fixed

* Labels and features were recomputed from the raw CSVs with code separate from the builders (1,500-row random sample per
  hazard): 0 mismatches; no duplicate (district, feature year) keys; target year = feature year + 1 everywhere; split
  target-year ranges heatwave train 2013-2019 / val 2020-2021 / test 2022-2025, flood 2012-2019 / 2020-2021 / 2022-2023,
  malaria 2013-2019 / 2020-2021 / 2022-2023.
* Leakage tests: features of year T are unchanged when all later years are altered; test labels do not change the weights,
  threshold or calibration; the flood cohort does not depend on validation/test labels.
* Defects found and fixed in ml/hazard_inference.py: (1) a non-string hazard raised TypeError; (2) heatwave returned a
  class label although its probability and threshold were withheld (it compared a raw score with a threshold chosen on the
  calibrated scale); (3) class labels (`flood_next_year_positive`) overstated a presence-only target. Labels now mirror the
  target wording and the class is null whenever the probability is withheld. Each fix has a regression test.
* Malaria rows require a FULL_YEAR record in T-1, T and T+1; a district that stops reporting is dropped (unknown, not zero).
  If drop-outs correlate with the outcome this selects slightly; it cannot be removed without inventing data.

## 12. Legacy work retained

The first heatwave experiment (`ml/prepare_heatwave_dataset.py`, `train_heatwave_models.py`,
`heatwave_inference.py`, v1 models and `ml/experiments/`) is kept as evidence and regression-tested,
but is **superseded** by the v2 pipeline above: it used a different split, no calibration, and a
test set that was inspected during audit. The authoritative ML interface is `ml/hazard_inference.py`.
